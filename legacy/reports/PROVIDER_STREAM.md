# Observable, bounded MiMo streaming

Production MiMo requests now stream by default (`Settings.provider_stream=true`). This extension improves transport evidence and public-draft recovery. It does not establish efficient autonomous company completion or profitable strategy production.

The assembler retains opaque reasoning in memory for the next actual tool turn and assembles indexed public tool arguments. It records progress counts, elapsed time, first-chunk delay and time since the last received chunk. Progress without received chunks is a client heartbeat, not evidence that the provider is producing output. Opaque reasoning text is never written to these records.

Tools may execute only after a terminal completion marker and stream EOF arrive before the wall deadline, followed by existing role, schema and artifact validation. Length-truncated, unterminated, refused, malformed and late streams cannot execute their tool calls. A bounded queue and response-size limit prevent unconstrained accumulation. The reader checks cooperative stop/deadline state while receiving or waiting. A request is always accounted for on interruption; terminal reported usage is used when available, otherwise its reservation remains charged. These are provider-reported token counts, not independent billing reconciliation or a remote cancellation guarantee.

Interrupted public content/arguments are stored as non-executable drafts. A fresh resumed task can use them without pretending the prior opaque conversation survived. A scientist must still commit a validated decision; an engineer must still submit actual code; a historian must still record grounded lessons. Task and campaign limits remain frozen. Controlled parser-error messages survive without embedding response text. General transport/SDK exception messages are omitted because they can contain untrusted response values.

MiMo's [official streaming/context documentation](https://mimo.mi.com/docs/en-US/usage-guide/passing-back-reasoning_content) shows streamed reasoning, a terminal marker and a subsequent usage chunk. Its examples permit `created` timestamps to change across chunks. The assembler retains the first timestamp and checks response/model identity separately. Interim usage cannot become the request charge before a terminal marker. MiMo's [chat API](https://mimo.mi.com/docs/en-US/api/chat) documents streamed deltas and warns that generated tool arguments can be invalid; transport completion never overrides local validation.

## Verified scope

The final full authored suite passed **256 tests in 77.34 seconds**, including stream fault cases, SDK/SSE integration, partial-draft recovery and the existing scientific, numerical and forward gates. The local HTTP SSE fixture used the installed SDK (2.24.0), two actual streamed HTTP responses and an actual tool result. It verified opaque-context pass-back and 130 synthetic reported tokens while confirming private text was absent from persisted events. Its provider and numerical evidence remain synthetic.

`verify_streamed_engineer.py` attempted one real implementation delivery in campaign `2b22519842f6`, under a frozen 35,000-token task cap, one-request allowance, 16,000 completion allowance, 900-second request deadline and fixed November 23 development replay target. It did not restart the scientist tests or original pilot. The stream failed early after three chunks and three opaque characters, before any public code or executable tool delivery. Its exact then-current `ValueError` message was not retained, so the cause cannot be retrospectively asserted. No candidate, numerical check or replay resulted. Its **29,228-token reservation remained charged**, with actual usage unknown. The process is terminal and the one-request test is exhausted. Receipt: `results/desk/verification/streamed-engineer/run.json`.

Inspection then found and corrected the erroneous fixed-`created` assumption, added safe protocol diagnostics and permitted interim/terminal usage handling. These changes have regression evidence. They do not prove the exact cause of that earlier real failure.

`verify_stream_transport.py` made one separately bounded small actual endpoint diagnostic with at most 512 completion tokens under a 4,000-token task cap. It assembled **seven chunks**, returned `{"transport_probe":true}` with finish reason `stop`, and received **42 reported tokens** (20 prompt, 22 completion, including 14 reasoning). Raw opaque text was not persisted. Usage appeared on chunk 6 after the terminal marker. All seven `created` timestamps happened to be equal in this short response, so this actual probe did not reproduce timestamp variation. It supplied no research tools, code, scientific decision or company acceptance. Receipt: `results/desk/verification/stream-transport/run.json`.

Current campaign accounting: **23 requests, 676,883 known actual tokens, 737,309 charged tokens**, leaving **12,691** of the unchanged original 750,000 allowance. The two ambiguous recent requests account for the difference. No budget increase, original cycle completion, holdout exposure or promotion occurred in these probes. Rerunning either verifier reports its existing receipt without making a new call.
